# План проекта: прогноз пассажиропотока метро

**Цель.** Прогноз пассажиропотока по одной линии метро на 7 дней вперёд с почасовой детализацией по станциям. Прогноз обновляется раз в день. Есть режим «что-если».

**Пилотная линия.** Сокольническая (1-я линия), 26 станций.

## Требования заказчика

| Параметр | Значение |
|---|---|
| Горизонт прогноза | 7 дней |
| Детализация | одна линия, станция × час |
| Точность | выше 85% на последнем году (MAPE < 15%) |
| Обновление | раз в день |
| «Что-если» | да: закрытие станции, событие, погода, изменение интервала движения |
| Фильтры | дата, станция, участок линии, время |
| Нормативы | на усмотрение команды (метрики MAPE, WAPE, MAE; валидация по времени) |

## Метрики успеха

- **Точность = 100% − MAPE** на тестовом году. Цель: ≥ 85%.
- **WAPE** как основная метрика для сравнения моделей: она устойчива к малым значениям в ночные часы.
- **MAE** в пассажирах за час: для понятной интерпретации.
- Технические: время ответа API < 300 мс (p95), прогноз пересчитывается ежедневно без ручных действий.

## Правила Kanban

Колонки: **Backlog → To Do (неделя) → In Progress → Review → Done**.

- WIP-лимит: не больше 2 задач в In Progress на человека.
- Каждая карточка: исполнитель, неделя, метка роли, ссылка на PR.
- Задача уходит в Done только после ревью и слияния в `main`.
- Блокеры помечаются красной меткой и разбираются на ближайшем стендапе.
