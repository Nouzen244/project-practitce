# Метрики успеха

Неделя 1 · ведёт Мамаев Никита (Product Owner)

## Метрики качества прогноза

Считаются на тестовом году: модель обучается на всех годах до него и последний год не видит.
Прогноз почасовой, по каждой станции.

| Метрика | Формула | Зачем | Цель |
|---|---|---|---|
| **MAPE** | среднее \|факт − прогноз\| / факт × 100% (без часов с потоком < 50 чел.) | главная метрика заказчика | ≤ 15% |
| **Точность** | 100% − MAPE | так формулирует заказчик | **≥ 85%** |
| **WAPE** | Σ\|факт − прогноз\| / Σ факт × 100% | устойчива к малым значениям, по ней выбираем модель | ≤ 12% |
| **MAE** | среднее \|факт − прогноз\|, пассажиров в час | понятна диспетчеру в людях | для справки |

Часы с потоком меньше 50 человек исключаются из MAPE. Например, 5 утра на малой станции:
ошибка в 10 человек даёт там 50%, и такие часы бессмысленно искажают среднее.

## Ориентир, который надо превзойти

Сезонный наивный прогноз: «столько же, сколько в этот час неделю назад». Если модель
не лучше него, она не нужна. Значения на каркасе проекта (синтетика, тест — 2025 год):

| Модель | MAPE | WAPE | Точность |
|---|---|---|---|
| Сезонный наивный | 13,2% | 11,0% | 86,8% |
| LightGBM (каркас) | 6,4% | 6,4% | 93,6% |

На синтетике цифры завышены, потому что данные «чище» реальных. Цель ≥ 85% проверяем
по той же процедуре и после каждого обновления данных.

## Метрики работы сервиса

| Метрика | Цель | Источник |
|---|---|---|
| Прогноз пересчитан за последние 26 часов | 100% дней | `forecast_last_run_timestamp` |
| Длительность пересчёта | < 5 мин | лог `forecast run` |
| Доля ошибок API (5xx) | < 1% | `/metrics` |
| Время ответа `/forecast`, 95-й перцентиль | < 1 с | `/metrics` |
| Проверки качества данных | 0 ошибок перед загрузкой | `reports/data_quality.json` |

## Метрики процесса команды

- Все карточки недели закрыты к пятнице. Перенос допускается с объяснением на ревью.
- В колонке In Progress у одного человека не больше 2 карточек (WIP = 2).
